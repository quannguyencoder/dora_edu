# Claude Project Instructions for DoraEdu

## Project Context

You are working on **DoraEdu**, a Python 3.14 RAG (Retrieval-Augmented Generation) application. Its goal is to act as a Telegram-based tutor for Vietnamese students. The system strictly uses official textbooks (PDFs) and MUST NOT hallucinate answers outside the provided context.

## Workspace Constraints

* **Project Blueprint:** To understand the module interactions, ALWAYS read the `dora_edu_architecture.md` file located in the root directory before proposing new features.

* **src-layout:** The code is located inside `src/dora_edu/`. When generating file paths, always refer to this structure.

* **Dependencies:** Managed via `pyproject.toml`. If you suggest installing a package, output the command to add it to `pyproject.toml` or install it (e.g., `pip install .`). Do not reference `requirements.txt`.

* **Python Version:** Assume Python 3.14 features are available.

## RAG Specific Rules

1. **Metadata Filtering:** Whenever you write ChromaDB query logic, you MUST implement metadata filtering. The query must always filter by `grade` and `subject` to ensure cross-grade data isolation.

2. **Prompt Engineering:** When writing system prompts in `prompts.py`, ensure the tone is encouraging (Socratic tutor) and explicitly forbids answering out-of-context questions.

3. **Data Privacy:** Assume textbook PDFs are sensitive. Never write code that uploads raw PDFs to public cloud storage without explicit instructions.

## Coding Standards

* Write clean, modular, and DRY (Don't Repeat Yourself) code.

* Provide comprehensive docstrings for all classes and methods in **English**.

* Use `pydantic` for data validation (e.g., validating the structure of Telegram webhook payloads or LLM responses).
